When you report a problem, say which version you have (the last line of the menu with Settings…), your macOS version, the server (Redis or Valkey, its version, standalone, cluster or sentinel) and what you did. Leave out passwords, host names and data you would not want public: issues are visible to everyone.

Common questions

redcrab cannot connect to my server.

Check that the host and port are reachable from your Mac, for example with redis-cli -h host -p port PING. A server that needs TLS needs TLS turned on in the connection; one behind a bastion needs an SSH tunnel. Cloud databases often allow only listed IP addresses. The error redcrab shows names the step that failed. More in Connections.

It says it cannot read my SSH key or certificate.

The Mac App Store version can only read files you pick yourself. Choose the file again with the folder button next to the field; redcrab keeps a private copy so it can read it next time.

Where is my SSH agent, or the Unix socket option?

The Mac App Store version runs in Apple's sandbox, which keeps it from reaching ssh-agent and local socket files. Use a key file for SSH and a host and port for the server, or use the version from GitHub, which has both.

Where are my connections and passwords kept?

Connections are saved on your Mac in redcrab's own folder; passwords and passphrases in the macOS Keychain, under "redcrab". Nothing is sent anywhere. See the privacy policy and what redcrab keeps on disk.

How do I update?

The Mac App Store updates its copy. A copy from GitHub looks for a new release once a day and asks before installing it, after checking it against redcrab's own signing key. Homebrew users can also run brew upgrade.

Can I open a database read-only?

Yes. Turn on Read-only in the connection: redcrab then refuses every command that writes, in the browser and in the console alike.

Security issues

Please do not report a security problem in a public issue. Use GitHub's private vulnerability reporting instead.
